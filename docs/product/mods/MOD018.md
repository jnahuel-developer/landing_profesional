# MOD018 — Accesibilidad, SEO y rendimiento

**Bloque:** 6 — Consolidación de la web base  
**Rama:** `mod018`  
**Base:** `develop` con `mod017` integrada  
**Dependencias:** producto base completo y observable  
**Estado:** Planificada  

## Objetivo

Realizar el endurecimiento transversal de experiencia, indexación y rendimiento antes de la regresión final.

## Alcance

- Auditar todas las rutas públicas con axe y revisión manual.
- Corregir foco, landmarks, encabezados, labels, errores y anuncios dinámicos.
- Verificar navegación completa por teclado.
- Verificar temas, contraste, zoom y reducción de movimiento.
- Revisar títulos, descripciones, canonical, `hreflang`, Open Graph y datos estructurados.
- Excluir `/admin`, rutas de sesión y endpoints de indexación.
- Validar sitemap y robots.txt.
- Optimizar fuentes, imágenes, carga diferida y límites de JavaScript cliente.
- Revisar Server Components y reducir hidratación innecesaria.
- Establecer presupuestos de rendimiento reproducibles.
- Ejecutar Lighthouse en páginas públicas representativas.

## Presupuestos iniciales

- Core Web Vitals sin degradaciones críticas en entorno de prueba controlado;
- Lighthouse Performance, Accessibility, Best Practices y SEO con objetivo mínimo de 90 en páginas comerciales principales;
- navegación y feedback inmediato en operaciones locales;
- vista imprimible preparada en menos de un segundo, sin contar el diálogo del navegador;
- ausencia de imágenes originales innecesariamente grandes.

Los valores se usarán como barrera de regresión, no como promesa de resultados idénticos en todos los dispositivos.

## Pruebas y verificaciones

- axe automatizado sobre rutas representativas;
- recorrido manual solo con teclado;
- zoom al 200 %;
- contraste de todos los temas;
- Lighthouse en home, soluciones, contacto y laboratorio;
- metadata y datos estructurados;
- sitemap, robots y rutas no indexables;
- análisis de bundles y assets;
- impresión de documentos de prueba del framework común cuando exista plantilla.

## Fuera de alcance

- rediseño general del producto;
- compatibilidad con navegadores obsoletos;
- CDN;
- optimización específica del VPS;
- pruebas de las futuras interfaces ACME.

## Criterios de aceptación

- [ ] No existen violaciones críticas conocidas de accesibilidad.
- [ ] Los recorridos principales pueden completarse solo con teclado.
- [ ] Las páginas públicas poseen metadata completa y coherente.
- [ ] Las rutas privadas o temporales no son indexables.
- [ ] Los presupuestos de rendimiento se cumplen en el entorno acordado.
- [ ] No quedan activos o scripts claramente innecesarios en la carga inicial.

## Condición del MR

El MR deberá adjuntar resultados comparables antes y después para accesibilidad, Lighthouse y tamaño de carga de las páginas revisadas.
