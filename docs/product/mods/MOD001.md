# MOD001 — Runtime, workspaces y aplicaciones mínimas

**Bloque:** 1 — Fundación ejecutable  
**Rama:** `mod001`  
**Base:** `develop` creado desde el `main` inicial  
**Dependencias:** Node.js 24 LTS y pnpm 11 disponibles  
**Estado:** Planificada  

## Objetivo

Transformar el bootstrap documental en un monorepositorio ejecutable. Al finalizar deberán iniciar una aplicación Next.js y una API Fastify mínimas, con configuración compartida y comandos raíz estables.

## Alcance

- Completar `packages/config` con bases TypeScript y ESLint compartidas.
- Configurar TypeScript estricto, ESM, aliases y resolución de workspaces.
- Inicializar `apps/web` con Next.js 16, React 19 y App Router.
- Inicializar `apps/api` con Fastify 5 y TypeScript.
- Incorporar Tailwind CSS a la aplicación web sin definir todavía el sistema visual final.
- Crear páginas técnicas mínimas para confirmar que web y API arrancan.
- Implementar carga y validación temprana de variables de entorno.
- Completar scripts `dev`, `build`, `lint`, `typecheck` y `start` de los workspaces.
- Mantener web y API como procesos locales; Docker continuará reservado a PostgreSQL y Mailpit.

## Entregables

- `apps/web` ejecutable en el puerto 3000.
- `apps/api` ejecutable en el puerto 4000.
- configuración compartida consumida por ambos workspaces;
- página técnica temporal con versión y estado de arranque;
- endpoint temporal `GET /api/v1` con identificación del servicio;
- `.env.example` actualizado con toda variable introducida;
- README raíz con procedimiento real de instalación y ejecución.

## Decisiones de implementación

- No se utilizarán Turborepo, Nx ni otro orquestador.
- Los scripts raíz delegarán mediante filtros pnpm.
- Ninguna aplicación importará archivos internos de otra aplicación.
- Los paquetes compartidos expondrán entradas públicas explícitas.
- La validación de configuración deberá fallar con mensajes claros, sin imprimir secretos.

## Pruebas y verificaciones

- `pnpm install --frozen-lockfile`;
- `pnpm format:check`;
- `pnpm lint`;
- `pnpm typecheck`;
- `pnpm build`;
- arranque simultáneo mediante `pnpm dev`;
- comprobación manual de los puertos 3000 y 4000.

## Fuera de alcance

- conexión con PostgreSQL;
- migraciones;
- healthchecks definitivos;
- sistema visual;
- páginas comerciales;
- tests automatizados completos.

## Criterios de aceptación

- [ ] Node.js 24 y pnpm 11 son rechazados si no cumplen los rangos declarados.
- [ ] `pnpm dev` inicia web y API sin errores.
- [ ] Ambos workspaces compilan con TypeScript estricto.
- [ ] El build de producción finaliza correctamente.
- [ ] No existen dependencias circulares entre workspaces.
- [ ] Las variables requeridas se validan al arrancar.
- [ ] La documentación permite reproducir el arranque desde un checkout limpio.

## Condición del MR

El MR solo podrá integrarse cuando los comandos raíz sean funcionales en Windows y CI mantenga, como mínimo, instalación y formato en verde.
