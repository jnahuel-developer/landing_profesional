# MOD015 — Catálogo, lanzador y shell del laboratorio

**Bloque:** 5 — Plataforma base del laboratorio  
**Rama:** `mod015`  
**Base:** `develop` con `mod014` integrada  
**Dependencias:** sesiones demo disponibles  
**Estado:** Planificada  

## Objetivo

Convertir `/lab` en el punto de entrada operativo de las demostraciones y construir el contenedor visual común que utilizarán ambos dominios.

## Alcance

- Implementar catálogo tipado de demos registradas.
- Registrar ACME Café y ACME Logística como entradas conocidas con estado **Próximamente**.
- Construir portada, cards, detalle breve y lanzador.
- Crear o recuperar sesión al ingresar al laboratorio.
- Implementar shell con navegación, ayuda, idioma, tema y temporizador.
- Mostrar estado de simulación y aviso de datos ficticios.
- Incorporar controles comunes de reinicio y salida.
- Preparar rutas estables para cada demo sin implementar su contenido interno.
- Implementar estados disponible, próximamente, mantenimiento y no encontrado.
- Registrar eventos analíticos del catálogo sin crear una sesión funcional innecesaria.

## Contrato mínimo de catálogo

- identificador y versión;
- nombre y descripción localizados;
- estado de disponibilidad;
- roles declarados;
- escenarios declarados;
- imagen o identidad visual local;
- rutas registradas;
- capacidades opcionales;
- política de sesión.

## Reglas

- La UI no contendrá listas duplicadas de demos.
- Solo una demo declarada como disponible podrá iniciarse.
- El estado **Próximamente** no simulará carga ni fallará como error técnico.
- El temporizador utilizará la expiración del servidor.
- Salir del laboratorio no destruirá automáticamente una sesión vigente.
- Reiniciar solicitará confirmación y explicará su alcance.

## Pruebas y verificaciones

- render de catálogo en ambos idiomas;
- estados de disponibilidad;
- entrada y salida del shell;
- temporizador y aviso de expiración;
- reinicio confirmado y cancelado;
- rutas desconocidas;
- teclado, foco y contingencia móvil;
- eventos analíticos categóricos.

## Fuera de alcance

- lógica interna de ACME;
- mapas, POS o aplicaciones móviles simuladas;
- escenarios funcionales reales;
- imágenes finales de prueba de entrega;
- recorridos guiados completos.

## Criterios de aceptación

- [ ] `/lab` funciona como catálogo y no como una página comercial duplicada.
- [ ] Las dos empresas aparecen con metadata coherente y estado honesto.
- [ ] El shell muestra sesión, tiempo restante y controles comunes.
- [ ] Una demo no disponible no puede iniciarse por manipulación de URL.
- [ ] Idioma y tema se conservan al entrar y salir.
- [ ] La experiencia es accesible y comprensible sin explicación externa.

## Condición del MR

El MR deberá demostrar el shell con una entrada técnica de prueba no visible en producción, suficiente para validar navegación y sesión.
