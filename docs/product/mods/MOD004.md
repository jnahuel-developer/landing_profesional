# MOD004 — Tokens, tipografía, temas y componentes base

**Bloque:** 2 — Sistema visual y shell global  
**Rama:** `mod004`  
**Base:** `develop` con el Bloque 1 cerrado  
**Dependencias:** `@portfolio/ui` ejecutable y pruebas configuradas  
**Estado:** Planificada  

## Objetivo

Implementar el sistema visual compartido que utilizarán el portfolio, el panel administrativo y el laboratorio.

## Alcance

- Convertir los valores visuales aprobados en variables CSS semánticas.
- Definir color, tipografía, espaciado, radios, sombras, capas, motion y breakpoints.
- Incorporar fuentes locales optimizadas mediante Next.js.
- Integrar Tailwind CSS con los tokens, sin duplicar valores arbitrarios.
- Incorporar primitivas Radix UI cuando resuelvan accesibilidad o interacción compleja.
- Implementar variantes clara, oscura y contraste reforzado previstas por la plataforma.
- Implementar densidad cómoda y compacta.
- Crear los componentes base necesarios para los bloques siguientes.

## Componentes iniciales

- `Button`, `IconButton` y enlace tipográfico;
- `Input`, `Textarea`, `Select`, `Checkbox` y `RadioGroup`;
- `Card`, `Badge`, `Alert` y `Callout`;
- `Dialog`, `DropdownMenu`, `Tabs` y `Tooltip`;
- `Skeleton`, indicador de carga y estado vacío;
- contenedores, stack, grilla y separadores;
- toast o feedback no bloqueante;
- iconos comunes con texto accesible cuando corresponda.

## Entregables

- API pública documentada de `@portfolio/ui`;
- hoja global de tokens;
- utilidades de tema y densidad;
- página interna de desarrollo para inspeccionar componentes, excluida de producción;
- ejemplos de estados normal, hover, focus, disabled, loading y error;
- guía breve de uso y composición.

## Reglas

- Los componentes no contendrán texto de negocio.
- Los colores de estado no dependerán únicamente del color.
- Todo control interactivo tendrá foco visible.
- Las variantes se resolverán por propiedades explícitas, no por copias del componente.
- No se incorporará Storybook en esta etapa.
- Se priorizarán componentes pequeños y composición sobre configuraciones extensas.

## Pruebas y verificaciones

- renderizado de variantes críticas;
- interacción por teclado;
- nombres y relaciones accesibles;
- contraste de combinaciones principales;
- cambio de tema y densidad;
- build tree-shakeable sin dependencias del servidor.

## Fuera de alcance

- layouts de páginas;
- navegación global;
- contenido comercial;
- gráficos del panel;
- componentes internos específicos de ACME.

## Criterios de aceptación

- [ ] Los tokens son la única fuente de valores visuales globales.
- [ ] Los componentes críticos funcionan con teclado y lector de pantalla.
- [ ] Tema y densidad pueden cambiar sin remontar la aplicación completa.
- [ ] No existen colores o tipografías de negocio incrustados en componentes base.
- [ ] La página interna muestra todos los estados aprobados.
- [ ] Las pruebas de UI y accesibilidad se encuentran verdes.

## Condición del MR

El agente deberá justificar cualquier token nuevo que no provenga de la línea visual aprobada. La comparación visual con los mockups será realizada por el propietario fuera de la ejecución de Codex.
