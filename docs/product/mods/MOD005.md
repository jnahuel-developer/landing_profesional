# MOD005 — Layout, navegación y pie global

**Bloque:** 2 — Sistema visual y shell global  
**Rama:** `mod005`  
**Base:** `develop` con `mod004` integrada  
**Dependencias:** sistema visual base disponible  
**Estado:** Planificada  

## Objetivo

Construir la estructura de página y navegación que contendrá toda la experiencia pública, manteniendo un diseño desktop-first y una contingencia usable en pantallas menores.

## Alcance

- Implementar layout raíz, límites de ancho y grilla principal.
- Crear cabecera, navegación primaria y acceso destacado a `/lab`.
- Crear pie con navegación secundaria, contacto y datos legales mínimos.
- Implementar indicador de sección activa.
- Añadir skip link y landmarks semánticos.
- Definir contenedores para páginas comerciales, laboratorio y administración.
- Añadir navegación móvil de contingencia sin rediseñar el producto como mobile-first.
- Gestionar estados sticky, scroll y foco al navegar.
- Centralizar las rutas visibles en una configuración tipada.

## Entregables

- `PublicLayout`;
- `LaboratoryLayout` preliminar;
- `AdminLayout` preliminar;
- componentes de cabecera, menú y pie;
- breadcrumbs donde resulten necesarios;
- placeholders de las rutas públicas aprobadas;
- páginas `not-found` y error técnico preliminares.

## Reglas

- La navegación no duplicará definiciones de rutas.
- Los enlaces usarán semántica nativa y estado de foco visible.
- El contenido principal no quedará oculto por elementos sticky.
- La contingencia móvil conservará acceso al contenido comercial.
- Las demos complejas podrán recomendar escritorio sin bloquear la navegación general.
- La cabecera no dependerá de JavaScript para mostrar enlaces esenciales.

## Pruebas y verificaciones

- navegación por teclado entre regiones;
- activación correcta de enlaces y estado activo;
- apertura y cierre accesible del menú reducido;
- layouts en resoluciones desktop, notebook y contingencia móvil;
- páginas de error navegables;
- ausencia de desplazamiento horizontal accidental.

## Fuera de alcance

- contenido comercial final;
- internacionalización;
- autenticación del panel;
- funcionalidades del laboratorio;
- animaciones narrativas complejas.

## Criterios de aceptación

- [ ] Todas las rutas aprobadas poseen un placeholder alcanzable.
- [ ] La navegación primaria funciona con y sin puntero.
- [ ] Existe un único `main` y una jerarquía semántica correcta por página.
- [ ] El acceso al laboratorio es visible sin dominar todos los recorridos.
- [ ] El layout se mantiene estable en las resoluciones soportadas.
- [ ] No se introducen dependencias de contenido específico de ACME.

## Condición del MR

El MR deberá incluir evidencia funcional de navegación por teclado y ausencia de desbordamientos en las resoluciones objetivo. No se exigirán capturas ni pruebas visuales; la aceptación estética corresponde al propietario.
