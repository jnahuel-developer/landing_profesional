# MOD011 — Consentimiento y analítica first-party

**Bloque:** 4 — Datos permanentes y panel interno  
**Rama:** `mod011`  
**Base:** `develop` con `mod010` integrada  
**Dependencias:** esquema `platform` y web comercial completa  
**Estado:** Planificada  

## Objetivo

Implementar medición propia y proporcional, activada únicamente después del consentimiento explícito del visitante.

## Alcance

- Crear tablas de eventos crudos, sesiones analíticas, agregados diarios y consentimiento.
- Implementar preferencias con opciones **Aceptar**, **Rechazar** y **Configurar**.
- Separar cookies estrictamente necesarias de analítica opcional.
- Crear identificador analítico pseudónimo y rotativo.
- Instrumentar páginas, CTA, navegación, contacto y presentación del laboratorio.
- Implementar endpoint de ingestión por lotes con taxonomía cerrada.
- Rechazar propiedades no declaradas.
- Crear consultas o proceso de agregación diaria ejecutable bajo comando.
- Aplicar retención de 180 días para eventos y 24 meses para resúmenes.
- Permitir modificar o retirar el consentimiento.

## Taxonomía inicial

- `page_view`;
- `navigation_used`;
- `cta_clicked`;
- `language_changed`;
- `theme_changed`;
- `contact_started`;
- `contact_submitted`;
- `contact_failed`;
- `lab_viewed`;
- `demo_card_selected`.

## Reglas

- Sin consentimiento no se enviarán eventos opcionales.
- No se almacenarán texto libre, mensajes, nombres, correos ni firmas.
- Las URL se normalizarán y excluirán query strings no permitidos.
- Los parámetros UTM aceptados se incluirán en una lista cerrada.
- No se realizará fingerprinting.
- La aplicación seguirá funcionando si la ingestión falla.
- No se utilizarán Google Analytics, Meta Pixel ni equivalentes.

## Pruebas y verificaciones

- primera visita sin decisión;
- aceptación, rechazo, cambio y retiro;
- cero eventos opcionales antes de aceptar;
- envío por lotes y reintento acotado;
- rechazo de propiedades desconocidas;
- filtrado de URL y UTM;
- expiración y agregación;
- navegación con analítica indisponible.

## Fuera de alcance

- gráficos del panel;
- alertas de negocio;
- heatmaps;
- grabación de sesiones;
- proveedores analíticos externos.

## Criterios de aceptación

- [ ] La elección de privacidad es explícita y reversible.
- [ ] Rechazar no degrada la web.
- [ ] Antes de aceptar no existe actividad analítica opcional.
- [ ] La API solo admite eventos y dimensiones documentados.
- [ ] Ningún evento contiene texto libre o datos de contacto.
- [ ] Retención y agregación pueden ejecutarse mediante comandos probados.

## Condición del MR

El MR deberá incluir una matriz que relacione cada evento con su disparador, propiedades permitidas y finalidad.
